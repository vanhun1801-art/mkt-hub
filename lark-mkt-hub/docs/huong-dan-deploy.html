Đưa Marketing Hub lên mạng

Ba chặng, khoảng 40 phút. Sau khi xong, cả phòng dùng chung một đường link; dữ liệu vẫn nằm nguyên trong Lark Base, Render chỉ là nơi chạy app và cấp domain.

CHẶNG 1
GitHub Cất code vào một chỗ Render đọc được — 10 phút
CHẶNG 2
Render Chạy app, lấy đường link công khai — 15 phút
CHẶNG 3
Lark Console Cho app quyền đọc Base và cho người dùng quyền vào — 15 phút

Chuẩn bị trước khi bắt đầu

  • Tài khoản GitHub (anh đã có: vanhun1801-art).
  • Tài khoản Render — sẽ đăng nhập bằng chính GitHub ở chặng 2, chưa cần tạo trước.
  • App Secret của app Lark cli_aa04305ecd385ed1. Lấy ở Developer Console → App → Credentials & Basic Info → ô App Secret → Copy. Dán tạm vào Notepad, chặng 2 cần.
  • Quyền admin trên Lark để phát hành version của app.

Một nguyên tắc: App Secret chỉ dán vào Render, không dán vào file code, không gửi qua chat. Nếu nó từng bị gửi đi đâu, vào Console bấm Reset rồi lấy cái mới.

CHẶNG 1

Đẩy code lên GitHub

github.com

  1. Tạo kho chứa code mới

    Mở github.com/new. Điền Repository name là mkt-hub.

    Chọn Private — bắt buộc. Repo public là công khai luôn cấu trúc Base, field ID và toàn bộ logic phân quyền.

    Đừng tích thêm README, .gitignore hay license — code đã có sẵn những thứ đó. Bấm Create repository.

    Thấy gì là đúng: trang hiện dòng chữ "Quick setup — if you've done this kind of thing before" kèm địa chỉ repo.

  2. Đẩy code lên

    Mở Command Prompt (bấm Windows, gõ cmd, Enter) rồi dán nguyên khối lệnh này:

    Command Prompt
    cd C:\Users\ASUS\.agents
git remote add origin https://github.com/vanhun1801-art/mkt-hub.git
git push -u origin main

    Lần đầu Git có thể mở một cửa sổ đòi đăng nhập GitHub — chọn Sign in with your browser rồi làm theo. Máy anh từng đẩy repo -mkt-tracking nên rất có thể nó nhớ sẵn và không hỏi gì.

    Thấy gì là đúng: dòng cuối ghi branch 'main' set up to track 'origin/main'. F5 lại trang GitHub sẽ thấy 4 thư mục lark-mkt-hub, lark-task-manager, lark-lich-tac-nghiep, lark-ads-manager.
    Nếu báo remote origin already exists: bỏ dòng git remote add, chạy hai dòng còn lại.

  3. Kiểm tra không có bí mật nào lọt lên

    Vẫn ở cửa sổ đó, chạy:

    Command Prompt
    git ls-files | findstr /I "ket-noi.json quyen.json muc-tieu.json .env"
    Thấy gì là đúng: không in ra gì cả. Nghĩa là token quảng cáo và file phân quyền cục bộ đã bị chặn, chỉ code lên GitHub.
CHẶNG 2

Chạy app trên Render

render.com

  1. Đăng nhập Render bằng GitHub

    Mở render.com → Get Started → GitHub. Render sẽ xin quyền đọc repo — chọn Only select repositories và tích đúng mkt-hub.

    Thấy gì là đúng: vào được Dashboard trống với nút New + ở góc trên phải.

  2. Tạo service từ bản thiết kế có sẵn

    Bấm New + → Blueprint → chọn repo mkt-hub → Connect.

    Repo đã có file render.yaml nên Render tự điền hết: tên mkt-hub, vùng Singapore, thư mục gốc lark-mkt-hub, lệnh chạy node server.js. Anh không phải nhập tay gì.

    Không thấy mục Blueprint? Dùng New + → Web Service rồi điền tay theo bảng ở bước 4.

  3. Điền bốn biến môi trường

    Render sẽ hỏi giá trị cho các biến đánh dấu "sync: false". Điền:

    Tên biếnĐiền gì
    LARK_APP_IDcli_aa04305ecd385ed1
    LARK_APP_SECRETApp Secret đã copy ở phần chuẩn bị
    PUBLIC_URLhttps://mkt-hub-w6hi.onrender.com — phải đúng tên miền Render cấp, xem bước 5
    LARK_MANAGER_IDSou_f0d3514abf6b168bef076441f350c585 (chính anh). Thêm quản lý khác thì viết tiếp, cách nhau bằng dấu phẩy

    SESSION_SECRET Render tự sinh, NODE_VERSION đã cố định là 22 — không cần chạm.

    Bấm Apply / Create. Render bắt đầu deploy, mất 1–3 phút.

    Thấy gì là đúng: log chạy tới dòng Marketing Hub · Rooty Trip Phú Quốc và trạng thái service chuyển sang Live màu xanh.

  4. Nếu phải điền tay (không dùng Blueprint)

    MụcĐiền
    Namemkt-hub
    RegionSingapore
    Root Directorylark-mkt-hub
    RuntimeNode
    Build Commandđể trống
    Start Commandnode server.js
    Instance TypeFree
    Health Check Path/healthz

    Rồi vào tab Environment thêm các biến ở bước 3, cộng thêm SESSION_SECRET. Sinh chuỗi này bằng:

    Command Prompt
    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

  5. Lấy đường link thật và sửa lại PUBLIC_URL

    Trên trang service, đầu trang có đường link dạng https://mkt-hub.onrender.com (nếu tên đã có người dùng, Render thêm hậu tố, ví dụ mkt-hub-a1b2). Copy đúng đường link đó.

    Vào tab Environment → sửa PUBLIC_URL thành đúng đường link → Save. Render tự deploy lại một lần nữa.

    Thấy gì là đúng: mở <link>/healthz trên trình duyệt thấy {"ok":true,...}. Mở trang chủ thì bị đẩy sang trang đăng nhập Lark — đúng, chặng 3 mới xong phần đăng nhập.
    Đây là lỗi anh vừa gặp. Render đặt tên service là mkt-hub-w6hi (vì mkt-hub đã có người dùng), mà PUBLIC_URL vẫn để mkt-hub.onrender.com → đăng nhập xong Lark trả về tên miền không phải của anh. Từ bản mới, app tự phát hiện và hiện luôn trang chỉ cách sửa thay vì im lặng.
CHẶNG 3

Cấp quyền trong Lark

open.larksuite.com

  1. Chia sẻ cả ba Base cho app

    Đây là bước hay sót nhất, và triệu chứng rất khó đoán: app vào được nhưng số liệu trống, hoặc log báo 91403.

    BaseLàm gì
    Tracking
    Bảng công việc    		 Base này nằm trong wiki nên chia sẻ ở cấp Base là chưa đủ: mở knowledge space chứa nó → Members → thêm app cli_aa04305ecd385ed1 với quyền Full access
    Lịch tác nghiệpMở Base → Share → thêm app, quyền Can edit
    Quản lý quảng cáoMở Base → Share → thêm app, quyền Can edit

  2. Khai đường quay về sau khi đăng nhập

    Developer Console → app của anh → Security Settings → mục Redirect URL → Add:

    dán vào ô Redirect URL
    https://mkt-hub-w6hi.onrender.com/auth/callback

    Đây đúng là link Render đã cấp cho anh (mkt-hub-w6hi, có hậu tố vì tên mkt-hub đã có người dùng). Sai một ký tự là lỗi redirect_uri mismatch.

  3. Khai app chạy ở đâu

    Features → Web App → điền cả hai ô Desktop homepage và Mobile homepage bằng đường link Render (không có /auth/callback).

    Nhờ bước này, app hiện ngay trong thanh bên của Lark, mọi người bấm là vào — không phải nhớ link.

  4. Chọn ai được vào app

    Availability (Phạm vi khả dụng) → chọn phòng Marketing, hoặc tích từng người.

    Đây là lớp quyền thứ nhất: ai mở được app. Lớp thứ hai — ai là quản lý — nằm ở biến LARK_MANAGER_IDS bên Render. Người không có trong biến đó vào với vai nhân sự: chỉ thấy việc của mình, không có tab quản lý.

  5. Phát hành

    Create Version → điền số version (ví dụ 1.0.0) → Save → Submit for release / Publish.

    Đừng bỏ bước này. Cấp quyền và khai URL mà không phát hành version thì mọi thay đổi ở chặng 3 chưa có hiệu lực — app vẫn báo 99991672.

Gửi cho phòng

  1. Gửi đường link Render vào nhóm Lark, kèm một câu: "Lần đầu mở sẽ hỏi đăng nhập Lark, bấm đồng ý là xong."
  2. Ai báo "không thấy dữ liệu của tôi" — kiểm Availability đã có tên họ chưa.
  3. Cần thêm một người làm quản lý: Render → Environment → thêm open_id của họ vào LARK_MANAGER_IDS, cách nhau bằng dấu phẩy → Save. Lấy open_id ở app Bảng công việc, nút Quyền.
  4. Sau này sửa code: chỉ cần git add -A, git commit -m "...", git push — Render tự deploy lại trong 1–2 phút.
Bản chi tiết hơn cho người quen kỹ thuật: lark-mkt-hub/docs/trien-khai-render.md trong repo.
